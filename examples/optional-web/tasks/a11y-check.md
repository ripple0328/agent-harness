# Task: a11y-check

## Use When

UI changed or a user asks for accessibility verification.

## Load

- `examples/optional-web/rules/web-ui.md`
- `examples/optional-web/roles/ui-specialist.md`
- relevant UI specs and design references

## Steps

1. Identify changed screens and components.
2. Check semantic structure.
3. Check labels, descriptions, and error associations.
4. Check keyboard reachability and focus visibility.
5. Check contrast where tooling or design tokens allow.
6. Check responsive and zoom behavior when relevant.
7. Run available automated accessibility tests.
8. Report evidence and gaps.

## Output

- accessibility findings
- commands or browser checks run
- screenshots or DOM evidence when available
- fix requests

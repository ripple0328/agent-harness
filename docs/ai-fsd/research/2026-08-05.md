## Learning Article

### Evidence-gated improvement: learning without chasing every trend

An agent harness is the environment that helps an AI agent deliver software
reliably: instructions, tools, repository knowledge, tests, permissions, and
feedback loops. Because agent products change quickly, it is tempting to copy
every new feature into that environment. The safer mental model is a funnel:

`discovery signal -> evidence -> bounded experiment -> verified adoption`

An X bookmark, demo, or release announcement enters the wide end of the funnel.
It tells us what may be worth investigating, but it does not prove that a new
workflow improves delivery. A signal moves forward only when an official source
or a local reproduction supports it and when it addresses a concrete delivery
problem. The experiment then changes one reversible surface and defines in
advance what success looks like.

Before this change, the harness had a strong inner feedback loop: a QA miss,
review correction, or audit finding could improve a rule or check. It did not
have a disciplined way to notice external advances or carry proven lessons
between projects. The applied change adds that outer loop while keeping the
existing evidence threshold. It deliberately does not install a vendor-specific
orchestration system merely because one now exists.

In another project, suppose a release note introduces agents that automatically
review pull requests. Do not immediately replace the review workflow. First name
the current problem, such as authorization defects escaping review. Run the new
reviewer on a small set of historical changes with known defects, compare its
findings with the current reviewer, and record false positives, misses, time, and
human attention. Adopt it only if the evidence shows a useful improvement and
the repository's security and permission boundaries remain intact.

The main failure mode is mistaking novelty for evidence. The opposite failure is
requiring so much proof that nothing can be tried. A bounded, reversible
experiment sits between those extremes: cheap enough to learn from, strict
enough not to turn a fast-moving feed into permanent process.

## Knowledge Check

1. Why is an X bookmark graded as a discovery signal rather than primary
   evidence?
2. What five stages make up the evidence-gated improvement funnel?
3. A new coding agent claims to reduce review time by 60%. What should be defined
   before changing the canonical review workflow?
4. When should a useful agent capability remain project-local instead of becoming
   a generic harness rule?

## Answer Key

1. It identifies something worth investigating but does not by itself verify the
   claim, applicability, or delivery outcome.
2. Discovery signal, evidence, bounded experiment, verification, and adoption.
3. The concrete current problem, baseline, test set, success measures, allowed
   scope, risks, and rollback.
4. When it depends on a particular product, stack, domain, architecture,
   permission model, release process, or unproven local assumption.

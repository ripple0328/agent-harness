# Task: commit

## Use When

The user wants to create a structured commit after review and verification.

## Load

- project-local commit conventions
- current diff
- linked spec or task

## Steps

1. Check working-tree status.
2. Summarize changed files.
3. Confirm review and verification status.
4. Stage only intended files.
5. Write a conventional or project-approved commit message.
6. Create the commit.
7. Report commit hash and any unstaged files left behind.

## Output

- commit hash
- commit message
- files included
- files intentionally not included

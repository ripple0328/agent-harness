# Task: define-adr

## Use When

A decision affects architecture, delivery process, data shape, security posture,
or future implementation choices.

## Load

- `harness/templates/adr.md`
- existing ADRs
- relevant specs and project-local rules

## Steps

1. State the decision pressure.
2. Capture the chosen decision.
3. List alternatives and why they were rejected.
4. Document positive and negative consequences.
5. Save as the next numbered ADR or project equivalent.
6. Link related specs.

## Output

- ADR path
- decision summary
- tradeoffs
- impacted specs or rules
